Everything you need to
orchestrate AI at scale

From local LLMs to cloud providers, single tasks to complex pipelines — nexus-orchestrator handles the routing, memory, and orchestration so you can focus on building.

🔀

Any model, one queue

LM Studio, Ollama, OpenAI, Anthropic, Gemini and any OpenAI-compatible endpoint, with discovery, health checks, role-based routing and automatic failover.

🎟️

Your subscriptions

Delegate to Claude Pro/Max through the logged-in claude CLI, and to GitHub Copilot and other editor models through the VS Code model bridge. No API key.

📡

Live output

The reply streams to the UI, VS Code and MCP clients while the model writes it. A failing provider hands over to the next one; partial text never reaches your file.

🧠

Project brain

SQLite FTS5 knowledge per repository, learned from CLAUDE.md, AGENTS.md, GEMINI.md and what agents ingest. Every session starts with a token-budgeted briefing.

📐

Rules that are enforced

.nexus/policy.json: default verification command, file-size limit, tests first, free-text rules. The engine enforces them on its own runs and remembers each outcome.

🗂️

Plans in any folder

PLAN-n / TASK-n files are found anywhere in the project (or in the folders you configure) and linked to each other automatically, whichever agent wrote them.

🔌

MCP server, 42 tools

Claude Code, Claude Desktop, Cursor, Antigravity and VS Code Copilot all use the same tools; wait_for_task streams progress. nexus-cli connect wires up the agents on your machine.

🤝

Agents report here

Agents register, claim a task and report its status through MCP, so what you see is what happened. Hand-edited state is shown as such: a task says who ran it.

🖥️

Full UI, everywhere

Mission Control, Agents, Providers, Projects (activity, plans, history, backlog, brain) and Settings, served by the daemon at /app/ and as a desktop app for macOS, Windows and Linux.

🧩

VS Code extension

Task queue, live output, plan view and brain commands in your editor; shares the editor models with Nexus and connects the editor's own agent (VS Code 1.101+, Antigravity).

🌐

REST API + CLI

Everything over HTTP with an SSE event stream, plus nexus-cli, nexus-submit and a GitHub Action for CI.

🛡️

Safe by default

Loopback only, origin and host guards, pre-flight context guard (TOO_LARGE), plan-first gate, verification with self-healing turns, zero telemetry.

Up and running in 60 seconds

  1. 1
    Start Nexus
    make start — daemon, REST on :63987, MCP on :63988, full UI at /app/ (or install the desktop app)
  2. 2
    Connect your agents
    nexus-cli connect --write adds Nexus to Antigravity, Cursor and Claude Code; the VS Code extension connects its own editor
  3. 3
    Add a provider
    LM Studio or Ollama are found automatically; add a cloud key, the claude CLI or the editor models
  4. 4
    Introduce a project and submit a task
    make init-project PROJECT=/path/to/repo, then submit via the UI, MCP, CLI or your editor
Full installation guide 
# From source (Node >= 22 builds the full UI)
make start
# REST      → http://localhost:63987
# Full UI   → http://localhost:63987/app/
# MCP       → http://localhost:63988/mcp

# macOS desktop app, no Gatekeeper dialog
curl -sSfL https://raw.githubusercontent.com/el-j/nexus-orchestrator/main/scripts/install.sh | sh -s -- --desktop
# Which agents on this machine can call Nexus? (changes nothing)
nexus-cli connect

# Connect them: Antigravity, Cursor, Claude Code
nexus-cli connect --write

# Teach Nexus a project once
make init-project PROJECT=/path/to/your/repo
curl -X POST http://localhost:63987/api/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "projectPath": "/path/to/project",
    "targetFile": "auth.go",
    "instruction": "Add JWT auth middleware",
    "command": "execute"
  }'
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "submit_task",
    "arguments": {
      "projectPath": "/path/to/project",
      "targetFile": "auth.go",
      "instruction": "Add JWT auth middleware"
    }
  }
}

Hexagonal architecture, ports & adapters

The core business logic never imports adapter code. All external concerns — LLMs, SQLite, filesystem — are abstracted behind interfaces for maximum testability and replaceability.
