# Audit of develop at 03bfb83 (v0.11.0-beta.16): definition-of-done check

Measured on 2026-10-31 against the owner's definition of done. Every number below was produced by a
command in this session (the commands are in the last section). The result is honest, not flattering:
the product works end to end, but **it does not yet meet "100 %" on coverage, documentation, mutation
testing or e2e**, and it carries a little dead code and a few oversized functions and test files.

## 1. Missing or outdated in-code documentation

- Go: 280 of 1 000 functions have no doc comment (54 are test doubles in `internal/testutil/fakes`).
  By package: `mcp` 67, `httpapi` 49, `sys_scanner` 23, `services` 22, `cli` 13, `llm_cli` 8, `repo_sqlite` 7.
  The `revive exported` rule only enforces exported identifiers on exported types, so these slip through.
- Exported methods without a comment are interface implementations (`Error`, `Write` in `mcp/server.go`,
  `mcp/sse.go`, `llm_cli/adapter.go`).
- TypeScript and Vue: `check:docs` passes (0 undocumented exported declarations); nothing found.
- Stale statements: `docs/agent-workflow-audit.md` says "It is **not yet** a system that makes agents follow
  your workflow" and counts 41 MCP tools; `docs/audit-v0.10.0.md` says 41/42; `docs/audit-v0.11.0.md` line 26
  says 40. There are 44. These are dated audits, but nothing marks them as superseded.

## 2. Gaps in the implementation

- **Unbounded history** (TASK-631): `GET /api/tasks/all` returns every task with logs: 93 MB and 3.2 s at
  20 k tasks; Mission Control calls it every 30 s. `GET /api/tasks` returns the whole queue (18.5 MB for 4 k).
  Instant at today's 142 tasks.
- **Dead frontend code**: `DiscoveryView.vue`, `AISessionsView.vue`, `TaskQueue.vue`, `AISessionCard.vue`,
  `ProviderStatus.vue` are imported nowhere (the router does not route the two views). They carry their own
  specs, so they count as 100 % covered.
- **Error swallowing by design**: 6 `nilerr` suppressions in `activity_network/reader.go` return `nil, nil`
  on failure; callers cannot tell "no activity" from "unreachable".
- **No frontend linter**: the frontend has no ESLint configuration (only `vue-tsc` and the TSDoc check).
- **Unused API-client exports** in `frontend/src/types/wails.ts` (`getTask`, `claimTask`, `updateTaskStatus`,
  `registerAISession`, `heartbeatAISession`, `authHeaders`): parity with REST/MCP (the surface matrix), but no
  view calls them.
- Antigravity **IDE** has no model API for extensions (verified earlier); only `agy` serves it. Documented.

unit-tested with fake CLIs and manually verified, but no e2e runs it through the daemon.

## 8. Performance

Measured on a loaded machine (load average 40+), so absolute numbers are pessimistic.

- Health, usage, small lists: 1-2 ms sequential. Daemon: 37 MB RSS idle, 162 MB with 20 k tasks.
- Fixed this round (PLAN-076): cache-lock probe contention, `agy models` every 30 s, log growth.
- Open: unbounded task history (above); the queue endpoint returns `logs` for every queued task.
- No Go benchmarks exist (`go test -bench` finds none); no performance regression gate.

## 9. Mutation testing

`make mutation` is local only by rule. Configured scope: Go core `domain`, `services`, `fs_writer`, `llm_cli`
with a 70 % efficacy gate; StrykerJS for frontend (break 72), extension (77), Action (75); none for the docs site.
A first run on `internal/core/domain` (still running when this was written, on a machine with load 40+) had
killed 20 mutants and let two live: `policy.go:100` and `policy.go:107` (`CONDITIONALS_BOUNDARY`), both
in the new project-policy validation, so those boundaries lack an assertion (TASK-643). 100 % is not reachable in practice (equivalent mutants are documented in
`docs/mutation-testing.md`); the realistic target is "no lived mutant in new code, gates raised step by step".

## How this was measured

`scripts/go-coverage.sh`-style merged profile (`go test -coverpkg=./... -coverprofile`), `golangci-lint run
--no-config --enable funlen,gocyclo`, a `go/ast` count of functions with and without doc comments, `git grep` for
stub markers and suppressions, `wc -l` over tracked files, a script comparing `httpapi` routes to the e2e sources,
a script finding unreferenced Vue/TS files, `npm audit`, `govulncheck`, `vue-tsc`/`tsc`, a scratch daemon with
20 142 tasks for the load figures.
