MCP Integration

Connect nexus-orchestrator to Claude Desktop and any MCP-compatible client.

# What is MCP?

The Model Context Protocol (MCP) is an open standard for connecting AI assistants to external tools and data sources. nexus-orchestrator implements an MCP server using JSON-RPC 2.0, making it compatible with Claude Desktop and any MCP-aware client.

# Claude Desktop Setup

Add the following to your Claude Desktop configuration file:

Config file path:

~/Library/Application Support/Claude/claude_desktop_config.json
{
  "mcpServers": {
    "nexus-orchestrator": {
      "url": "http://localhost:63988/mcp"
    }
  }
}

Config file path:

%APPDATA%\Claude\claude_desktop_config.json
{
  "mcpServers": {
    "nexus-orchestrator": {
      "url": "http://localhost:63988/mcp"
    }
  }
}

Restart Claude Desktop after editing the configuration. The nexus-orchestrator tools will appear in Claude's tool palette. Make sure the nexus-daemon is running before starting Claude Desktop.

# VS Code Setup

Add the following to your VS Code MCP configuration file:

macOS / Linux

~/Library/Application Support/Code/User/mcp.json

Windows

%APPDATA%\Code\User\mcp.json
{
  "servers": {
    "Nexus Orchestrator": {
      "type": "http",
      "url": "http://127.0.0.1:63988/mcp"
    }
  }
}

Use "type": "http" (Streamable HTTP), not "type": "sse". The SSE transport holds a session in memory; a daemon restart invalidates it, causing 400 errors and "terminated / Failed to parse message" noise in the VS Code output panel. Streamable HTTP is stateless and reconnects cleanly every time. Reload the VS Code window after saving the configuration.

Request

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "submit_task",
    "arguments": {
      "projectPath": "/path/to/project",
      "targetFile": "handler.go",
      "instruction": "Add error handling to the HTTP handler",
      "command": "execute"
    }

The MCP server supports both initialize and tools/list lifecycle methods, and all tool invocations via tools/call.

# Troubleshooting

Connection refused: Make sure the nexus-daemon is running and the MCP port (default 63988) is not blocked by a firewall.

No tools appearing: Verify the URL in claude_desktop_config.json ends with /mcp (not just the host:port).

IssueSolution
Connection refusedStart nexus-daemon first: ./nexus-daemon
Port conflictUse NEXUS_MCP_ADDR=:9090 to change the MCP port
No tools in ClaudeCheck URL ends with /mcp, restart Claude Desktop
Task stuck in QUEUEDCheck GET /api/providers — ensure at least one LLM provider is active

# GitHub Actions

Use nexus-orchestrator directly inside any GitHub Actions workflow. The Node.js 20 action downloads a local daemon, resolves agent identities from el-j/agency-agents, submits your task to the LLM, polls until completion, and returns the result as step outputs — all in a single step.

Basic Usage

# .github/workflows/ai-task.yml
name: AI Code Generation

on:
  workflow_dispatch:
    inputs:
      instruction:
        description: 'What should the LLM implement?'
        required: true

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Submit AI task
        id: nexus
        uses: el-j/nexus-orchestrator@v1
        with:
          instruction: ${{ github.event.inputs.instruction }}
          target_file: 'output.go'
          command: execute
          openai_api_key: ${{ secrets.OPENAI_API_KEY }}

      - name: Show result
        run: echo "${{ steps.nexus.outputs.logs }}"

Built-in Agent Identities

Use the agent input to select a specialist from el-j/agency-agents — no separate step required. The system prompt is fetched and prepended automatically. Use agents for a named swarm or agent_category to load every agent in a category. 

# Single agent — identity loaded automatically from el-j/agency-agents
jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Submit AI task as Backend Architect
        id: nexus
        uses: el-j/nexus-orchestrator@v1
        with:
          agent: engineering-backend-architect   # fetched from el-j/agency-agents@main
          instruction: 'Add JWT authentication middleware to the HTTP handler'
          target_file: 'internal/middleware/auth.go'
          command: execute
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}

      - name: Commit generated code
        if: steps.nexus.outputs.status == 'COMPLETED'
        run: |
          git config user.name "nexus-bot"
          git config user.email "nexus-bot@users.noreply.github.com"
          git add -A
          git commit -m "feat: AI-generated auth middleware" || echo "nothing to commit"
          git push
# Swarm — load all engineering agents and orchestrate as a team
jobs:
  swarm:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Submit task to engineering swarm
        id: nexus
        uses: el-j/nexus-orchestrator@v1
        with:
          agent_category: engineering        # loads all agents in the category
          instruction: 'Design and implement a rate-limiter for the API'
          command: plan
          openai_api_key: ${{ secrets.OPENAI_API_KEY }}
          openai_model: gpt-4o

Key Inputs

InputDefaultDescription
instruction—Task text sent to the LLM (required unless task_file is set)
task_file—Path to a .md/.txt file whose content becomes the instruction
agent""Single agent slug from el-j/agency-agents (e.g. "engineering-backend-architect")
agents""Comma-separated agent slugs — generates a combined swarm prompt
agent_category""Load ALL agents in a category (e.g. "engineering", "design", "testing")
agent_refmainGit ref of el-j/agency-agents to fetch from (branch, tag, SHA)
system_prompt""Raw system prompt override — takes precedence over agent/agents/agent_category
target_file""Relative path the LLM should write (e.g. src/utils.go)
commandexecute"plan" (orchestration) or "execute" (code generation)
openai_api_key""OpenAI API key — enables GPT models on the local daemon
anthropic_api_key""Anthropic API key — enables Claude models on the local daemon
github_copilot_token""GitHub Copilot token — enables GPT-4o via Copilot
timeout_seconds300Seconds to wait for task completion before failing
nexus_versionlatestRelease version to install (e.g. v0.2.0)
start_daemontrueDownload + start a local daemon; set false to use daemon_url
daemon_urlhttp://127.0.0.1:63987URL of existing daemon (only when start_daemon=false)
