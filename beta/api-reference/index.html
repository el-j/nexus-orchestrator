API Reference

HTTP REST API

Base URL: http://localhost:63987

Authentication and local-access protection

By default the daemon trusts local callers. Three layers protect it:

  • Bearer token (optional). Set NEXUS_API_TOKEN (or rotate one via PUT /api/config) and every /api/* request except /api/health, /api/howto and /.well-known/nexus.json must send Authorization: Bearer <token>. The MCP server uses NEXUS_MCP_TOKEN the same way.
  • Browser origin check (always on). A request carrying an Origin header that is not a local origin (localhost, 127.0.0.1, [::1], wails://wails.localhost) is rejected with 403. This stops a web page you happen to visit from driving the daemon with a cross-site request. CLI tools, the MCP stdio proxy and curl send no Origin and are unaffected. Add trusted origins with NEXUS_ALLOWED_ORIGINS (comma-separated, e.g. https://dash.example.com).
  • Host check (loopback binds). When NEXUS_LISTEN_ADDR is a loopback address, the Host header must be localhost or an IP literal, which defeats DNS-rebinding. Add host names with NEXUS_ALLOWED_HOSTS. A daemon deliberately bound to all interfaces (containers, LAN) skips the Host check - set NEXUS_API_TOKEN there.

Discovery

GET /.well-known/nexus.json

A public beacon (no token needed) that tells a tool or agent where everything is: api.base_url, api.howto, api.health, api.events, and mcp.endpoint, the full URL of the MCP server on its separate port. The MCP endpoint is built from NEXUS_MCP_ADDR; when that address has no host (:63988, 0.0.0.0:63988) the host you used to reach the REST API is reused. mcp.endpoint is omitted when the daemon does not know the address.

Error bodies are always {"error": "<message>"}. Server faults (5xx) never include internal details.

Submit Task

POST /api/tasks

Submit a new code-generation task to the queue.

Request Body:

{
  "projectPath": "/path/to/project",
  "targetFile": "output.go",
  "instruction": "Write a function that sorts strings",
  "contextFiles": ["main.go", "utils.go"],
  "modelId": "codellama",
  "providerHint": "LM Studio",
  "command": "execute"
}
Field Required Description
projectPath Yes Absolute path to the project directory
targetFile Yes Relative path for the generated output file
instruction Yes Natural language prompt for the LLM
contextFiles No List of files to include as context
modelId No Constrain to a specific model
providerHint No Prefer a specific provider by name
command No Task type: plan, execute, or auto (default: auto)
providerName No Lock routing to this exact provider
role No Routing tier: architect/techlead prefer frontier providers, coder/tester/linter prefer local ones
priority No 1 = high, 2 = medium (default), 3 = low
tags No Free-form labels
agentic No Run as a multi-turn tool loop (see below)
maxAgentTurns No Upper bound on model turns when agentic (default 8, max 25)

Response: 201 Created

{ "task_id": "a1b2c3d4-e5f6-...", "status": "QUEUED" }
Status Meaning
400 Body is not valid JSON
422 command is execute but the project has no completed plan task
429 The queue is full (queueCap). Transient: honour the Retry-After header and retry later

Agentic tasks

With "agentic": true the model no longer answers once and has the answer written to targetFile. Instead it works over several turns, replying each time with fenced ```nexus-tool blocks holding one JSON call each, and the daemon answers with the results:

Tool Arguments Effect
read_file path Returns the file (truncated to 16 KiB)
write_file path, content Creates or replaces a whole file
edit_file path, old, new Replaces the single exact occurrence of old; refused when old is missing or occurs more than once
verify none Runs the task's verificationCommand
finish summary Ends the task; refused while the verification command still fails

Safety: all file access is confined to projectPath (absolute paths, .. and symlinks that leave the project are rejected, and the model is told so). There is no tool that runs an arbitrary command; only the verificationCommand the task was submitted with can run. At most 8 calls of one reply are executed, the loop stops after maxAgentTurns turns (status FAILED), the transcript must fit the provider's context window (otherwise TOO_LARGE, or the next provider in the chain is used), and DELETE /api/tasks/{id} aborts a turn that is in flight. A task re-queued by a daemon restart starts again from the first turn; files already written remain.

Cancel Task

DELETE /api/tasks/{id}

Cancel a task. Which states can be cancelled:

Task status What happens
QUEUED, DRAFT, BACKLOG, NO_PROVIDER Moved to CANCELLED immediately.
PROCESSING (running in this daemon) The in-flight provider request is aborted; the task becomes CANCELLED a moment later (watch the task.cancelled event). It is not retried and does not fall back to another provider.
PROCESSING (claimed by an external agent) Taken off the board as CANCELLED; the external agent cannot be interrupted.
COMPLETED, FAILED, CANCELLED, TOO_LARGE Not cancellable.

When the daemon shuts down, a task that was running goes back to QUEUED (it is not marked failed).

Response: 204 No Content on success, 404 Not Found if the task doesn't exist, 409 Conflict if its status cannot be cancelled.

SSE Event Stream

GET /api/events

Server-Sent Events stream for real-time updates. Every frame is a plain data: line carrying a JSON object whose type field says what happened (there is no SSE event: field, except for log frames, see below). The first frame is {"type":"connected"}.

Task events ({"type": "...", "taskId": "...", "status": "..."}):

type Description
task.queued Task was added to the queue
task.processing Task is being processed by an LLM
task.completed Task completed successfully
task.failed Task processing failed
task.cancelled Task was cancelled (also after aborting a running one)
task.too_large Task exceeded the context window
task.no_provider No provider available for the task
task.draft A draft was created
task.backlog A task was moved to the backlog
task.updated A task's fields were edited

Other events:

type Payload Description
ai_session_changed aiSessionId, status, timestamp A session registered, heartbeated or went idle
ai_session_terminated aiSessionId, status, timestamp A session was terminated
ai_activity_new activity (an AI activity record) A new agent activity was observed
provider_discovered count A provider scan finished (refresh your list)

Log frames use a named event so they can be told apart:

event: log
data: {"timestamp":"2026-01-01T12:00:00Z","level":"info","source":"httpapi","message":"..."}

Frame format:

data: {"type":"task.completed","taskId":"abc-123","status":"COMPLETED"}

Slow clients are skipped rather than blocking the daemon, so a client that reconnects should re-read the state it cares about (for example GET /api/tasks) instead of relying on having seen every frame.

Ingest Project Knowledge

POST /api/brain/ingest

Parses and ingests a markdown file into the project context brain.

Request Body:

{
  "projectPath": "/path/to/project",
  "filePath": "CLAUDE.md"
}

filePath is resolved relative to projectPath when it is not absolute. Because the daemon reads the file on the caller's behalf, the request is confined (the same rules apply to the MCP ingest tool, the CLI, and the desktop app):

  • the file, after resolving symlinks, must be inside projectPath (a symlink that points out is refused);
  • it must be a regular file of at most 1 MiB;
  • anything below .ssh, .gnupg, .aws, .kube, .azure, .docker or .git, and files named .env*, .netrc, .npmrc, id_rsa or id_ed25519 are refused even inside the project;
  • projectPath must be an existing directory other than the filesystem root;
  • to ingest shared templates that live elsewhere, list their directories in NEXUS_INGEST_ALLOWED_DIRS (separated like PATH).

Response: 200 OK

{
  "ingestedSections": 5
}

Errors: 403 when the path is refused ({"error": "path not allowed: … is outside the project"}), 404 when the file does not exist, 400 when projectPath or filePath is missing.

Ingest Uploaded Content

POST /api/brain/ingest-content

Ingests markdown sent in the request instead of read from disk. This is what the dashboard and the desktop app use for "Ingest File…": a browser file has no path the daemon could read, so its content is uploaded. Nothing is read from the daemon's filesystem, so no path rules apply; the size limit does.

Request Body:

{
  "projectPath": "/path/to/project",
  "name": "notes.md",
  "content": "# Notes\n\n## Architecture\n..."
}

name is only a label (stored as the source upload:notes.md; any directory part is dropped). content is parsed like a CLAUDE.md: each ## section becomes a knowledge entry.

Response: 200 OK with {"ingestedSections": 3}.

Errors: 400 when projectPath or content is missing, 413 when content is larger than 1 MiB, 501 when the running brain service cannot ingest uploads.

Task coordination (for AI agents)

Agents that pull work from the queue instead of submitting it use these routes. Each takes the agent's sessionId (see AI sessions below).

Route Purpose

Task Lifecycle

QUEUED → PROCESSING → COMPLETED
                    → FAILED
                    → TOO_LARGE (pre-flight)
                    → NO_PROVIDER (no backend)
QUEUED → CANCELLED (user cancellation)

A task moves through these states:

  1. QUEUED: Submitted and waiting in the queue
  2. PROCESSING: Picked up by the worker, LLM call in progress
  3. Terminal state: One of COMPLETED, FAILED, TOO_LARGE, NO_PROVIDER, or CANCELLED
